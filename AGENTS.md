# Working on the public examie repository

This is a product showcase. The application is developed in a separate, private repository.

- Keep README.md, README.kk.md and README.ru.md aligned. English is the default page; the app’s learning languages are Kazakh and Russian.
- Write plainly. Describe what the product does and what was actually checked. Do not invent usage figures, testimonials, exam results or release claims.
- Do not use dot separators between links or labels. Keep language links spaced apart without decorative symbols. Prefer short prose to slogans, arrow sequences or repetitive feature lists.
- Only add material deliberately prepared for public viewing. Do not sync folders or history from the private repository.
- Write examples independently, with synthetic data and no private imports or live service calls. Label them as examples rather than application source.
- Do not add private implementation code, prompts, question banks, infrastructure details, environment files, credentials, database exports or user records.
- Screenshots must use test data. Inspect each image and record its date, language and platform in media/README.md. Do not present a mockup or a web capture as a native device capture.
- Check every proposed file and link before publishing. A file being untracked or ignored is not proof that it is safe to share.
- Run the documented example and its tests when changing code. Use Conventional Commits and preserve unrelated work.

The screenshot assets are intentional public demonstration material. Do not add a blanket open-source license without the owner’s instruction.
