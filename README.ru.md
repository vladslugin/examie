## Как устроена подготовка

Ученик выбирает предметы и решает задания по темам. После ошибки можно посмотреть объяснение и попробовать ещё раз. Непонятный шаг можно обсудить с Алтын, ИИ-репетитором, или отправить ему фото задачи.

Для повторения есть конспекты и короткие видеоуроки с вопросами для самопроверки. Приложение разрабатывается для iOS, Android и браузера. Для родителей и учителей предусмотрены отдельные кабинеты.

## ИИ и адаптивное обучение

### Как объясняет Алтын

Алтын объединяет внешние языковые модели с поиском по учебным материалам (RAG). Поиск учитывает смысловую близость и текстовые совпадения, предмет и язык. Найденные фрагменты могут дать контекст для объяснения. Если подходящего материала нет, ответ нельзя считать подтверждённым источником.

Задачу можно принести в виде фото или обсудить голосом. Приложение связывает распознавание изображений и речи, озвучивание и учебный диалог. Для поддерживаемых математических форматов отдельные проверки сверяют конкретные части решения, в том числе некоторые шаги с уравнениями. Область этих проверок ограничена.

[![Голосовой интерфейс Алтын с примером разбора квадратного уравнения](media/altyn-voice-preview-ru.jpg)](media/altyn-voice-preview-ru.jpg)

Предпросмотр голосового интерфейса от 24 октября 2026 года. Объяснение задано тестовым текстом; микрофон и речевые сервисы не включены. Кнопки режима разработки оставлены в кадре.

### Подбор заданий и оценка уровня

Адаптивная оценка использует IRT 2PL. После ответов обновляются оценка уровня ученика и её неопределённость. При выборе следующего задания учитывается, сколько информации оно даст об этом уровне. Одной сложности задания для этого недостаточно.

Прогноз балла сочетает IRT с методом Монте-Карло и выдаёт диапазон. Он отражает неопределённость внутри модели. Точность прогноза реального ЕНТ ещё предстоит проверить на результатах учеников, которые не использовались при построении модели.

Это реализованные части проекта в разработке. Алтын использует внешние модели. Собственная работа examie — их интеграция, учебные материалы, поиск, математические проверки и логика оценки.

## Код, который можно запустить

Эти примеры написаны отдельно для публичного репозитория и работают на вымышленных данных. Исходники приложения остаются закрытыми.

### Сложность зависит от уровня

У одного задания не должна быть одинаковая вероятность правильного ответа для всех учеников. Небольшой пример 2PL связывает оценку уровня со сложностью и различающей способностью задания:

```js
const logit = discrimination * (ability - difficulty);
const tail = Math.exp(-Math.abs(logit));
return logit >= 0 ? 1 / (1 + tail) : tail / (1 + tail);
```

Такая запись избегает переполнения экспоненты. При равных уровне и сложности получится 50%. Параметры здесь вымышленные; пример не обучает модель и не прогнозирует балл экзамена. Здесь есть [полный пример](examples/item-response/probability.mjs), [тесты](examples/item-response/probability.test.mjs) и [пояснение с инструкцией запуска](examples/item-response/README.md).

### Повторный просмотр

Если посмотреть секунды 0–30, а затем 20–50, получится 50 секунд урока, а не 60. После проверки интервалов, ограничения длительностью видео и сортировки остаётся небольшой расчёт:

```js
let watched = 0;
let coveredUntil = 0;

for (const [start, end] of ranges) {
  watched += Math.max(0, end - Math.max(start, coveredUntil));
  coveredUntil = Math.max(coveredUntil, end);
}
```

Исходный массив не меняется, пропущенные при перемотке участки не засчитываются. Здесь есть [полный пример](examples/lesson-progress/progress.mjs), [тесты](examples/lesson-progress/progress.test.mjs) и [инструкция запуска](examples/lesson-progress/README.md#run).

### Запоздавший ответ

Ученик перешёл к заданию B, пока подсказка к A ещё загружается. Старый ответ не должен заменить новый. Сначала отменяем предыдущую операцию, затем проверяем номер запроса перед обновлением экрана. Проверка нужна и после отмены: операция может проигнорировать сигнал.

```js
const value = await load(controller.signal);

if (requestId !== currentId) return "discarded";

apply(value);
return "applied";
```

При уходе с экрана ожидающий запрос тоже становится неактуальным. Ошибка текущего запроса доходит до вызывающего кода, чтобы экран мог показать её или предложить повторную загрузку. Здесь есть [полный пример](examples/latest-request/latest-request.mjs), [тесты](examples/latest-request/latest-request.test.mjs) и [инструкция запуска](examples/latest-request/README.md#run).

Все три примера запускаются локально на Node.js 22 или новее, без установки пакетов, ключей и обращений к сети.

## Разработка

Приложение ученика написано на React Native, Expo и TypeScript. Веб-кабинеты используют Next.js, серверная часть работает на NestJS и FastAPI с PostgreSQL и Redis.
